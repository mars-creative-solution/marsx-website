# design-sync notes — MarsX website

This repo is a Next.js marketing site, not a published component library — there's no `dist/`, no `.d.ts` exports, no Storybook. The sync uses the **package shape's synth-entry fallback** (scans `components/` directly) plus a forked `source-kit.mjs` to work around several repo-specific issues. Read this before re-syncing.

## Known, permanent limitations (not bugs to keep chasing)

- **`next/image` never resolves its real photo outside a live Next.js server.** `NasserFigure`, `NasserStage`, and `AmbassadorsShowcase` render actual portrait photos via `next/image`, which always requests through `/_next/image?url=...` — an endpoint only a real Next.js server provides. In claude.ai/design (and in this sync's own previews) that request 404s, and the component falls back to its own built-in graceful placeholder (name + icon + "temporary placeholder" text) rather than crashing. This is expected and permanent for this shape; the placeholder is a real, intentional state of the component, not a broken render.
- **`Button`, `Nav`, `Footer`, `Hero`, `NasserHero` are excluded entirely** (see the `source-kit.mjs` fork below) — they import `next/link`/`next/navigation`, whose client runtime needs a real Next.js router context.
- **`AboutContent`, `ContactContent`, `PlatformContent`, `SolutionsContent`** are synced (import fine) but intentionally left on the floor card — they're full-page compositions, not reusable components, per the scoping decision made at sync time.
- **Two `@font-face` rules ("Exo 2", "Inter") reference fonts that aren't shipped** (`[FONT_DANGLING]`, non-blocking). The actual files live under Next's build output (`.next/static/media/*.woff2`) with a per-build content hash — not a stable path to wire into `cfg.extraFonts` without re-solving the same hashing problem as the CSS (see below). Left as a known, accepted gap; the bundle's own Tailwind system-UI fallback is close enough for card previews.

## Repo-specific config/fork decisions

- **`cfg.cssEntry` can't point at Next's real compiled CSS directly** — the filename is content-hashed per build. Fixed with `.design-sync/copy-css.mjs` (part of `cfg.buildCmd`): copies the largest `.next/static/chunks/*.css` file to a stable `.design-sync/.cache/compiled.css` path. Re-run `npm run build` before every sync so this reflects current styles.
- **`node_modules/marsx` is a Windows directory junction to the repo root** (`New-Item -ItemType Junction`, not a symlink — plain `ln -s` hit "Too many levels of symbolic links" on this repo's self-referencing package name). This is what lets `--node-modules ./node_modules` resolve `PKG_DIR` to the repo root without a real npm-installed copy. Recreate it after a fresh clone: `New-Item -ItemType Junction -Path node_modules\marsx -Target <absolute-repo-root>`.
- **`.design-sync/overrides/source-kit.mjs` is a fork of the package adapter** (declared in `cfg.libOverrides`) with two repo-specific additions:
  1. Excludes `components/_backup/` (dead code) and `components/preview/` (unapproved experiments) from the src scan — both share component names with real components (`Hero`, `Footer`, `Nav`, `OrbitLogo`), which would otherwise collide.
  2. Excludes `Button.tsx`/`Nav.tsx`/`Footer.tsx`/`Hero.tsx`/`NasserHero.tsx` outright (next/link or next/navigation — crashes the synthesized entry outside Next).
  3. **Rewrites the synthesized entry to use explicit named re-exports** (`export { default as Name } from path`) instead of the naive `export * from path`. Every real component here is `export default function Name() {}` (Next.js convention), and ES `export *` never re-exports `default` — the naive entry left `window.MarsX` completely empty ([BUNDLE_EXPORT] 24/24 failing) until this fix. This is likely a real gap in the stock converter for any Next.js-style repo using default exports throughout, not something specific to MarsX.
- **`cfg.extraEntries: [".design-sync/process-shim.mjs"]`** — `next/image` reads `process.env.__NEXT_IMAGE_OPTS` at module top-level; with no `process` global in a browser IIFE that's a `ReferenceError` that crashes the *entire* bundle (not just the one component). The shim installs an empty `process.env` object before the main entry evaluates. Low-risk (never fakes real values, just prevents the reference from throwing).
- **`cfg.overrides`**: `IndustriesGrid`, `NasserStage`, `OrbitRings`, `ParticleField` are set to `{"cardMode": "column"}` — their authored previews render wider than the product's grid cell.

## Local grading tooling (never uploaded, gitignored)

`.ds-sync/package-capture.mjs` has one local-only edit: the stock `page.clock.setFixedTime(...)` call is removed. Playwright's Clock API virtualizes `requestAnimationFrame`, so with it installed, Framer Motion's animation loop (used throughout this repo's `whileInView`/`animate` patterns) never advances — every scroll-reveal element gets captured frozen at `opacity:0` regardless of any `waitForTimeout`. MarsX has no date-rendering components that need a fixed clock, so this was safe to drop for this repo. **If package-capture.mjs is ever re-staged from a fresh `cp -r`, this edit is lost — re-apply it before recapturing**, or grading screenshots will look blank again for any component using scroll-reveal animation.

Most authored previews (`AmbassadorsShowcase`, `PageHeader`, `CustomizeSection`, `DeployAnywhere`, `HowItWorks`, `SolutionsPreview`, `IndustriesPreview`, `ContactCTA`, `ImmersiveShowcase`, `IndustriesGrid`, `Nameplate`, `HoloHud`) additionally wrap their composition in `<MotionConfig reducedMotion="always">` (imported directly from `framer-motion`, not through the `marsx` bundle) so the card shows content fully revealed rather than mid-scroll-trigger — this affects only the preview's own rendering, never the real component.

## Re-sync risks (read before the next sync)

- The `node_modules/marsx` junction and the `copy-css.mjs` cache file are both machine-local, gitignored state — recreate them after any fresh clone (junction) or before any rebuild (`npm run build && node .design-sync/copy-css.mjs`, already wired into `cfg.buildCmd`).
- The package-capture.mjs local edit (dropped fixed clock) does not survive a fresh `cp -r` from the skill's bundled scripts — re-apply it, or any future re-grading of scroll-reveal components will silently show blank/frozen captures again, exactly as it did before this was diagnosed.
- The `export { default as ... }` entry rewrite lives in the forked `source-kit.mjs`, not in a config field — if this repo's components shift to named exports instead of default exports, the fork's logic still works (falls back correctly) but is no longer necessary; no action needed either way.
- `NasserFigure`/`NasserStage`/`AmbassadorsShowcase` will keep showing the graceful placeholder (not the real portrait) in claude.ai/design permanently, not just during this sync — there's no fix within this converter's scope (would require either a next/image loader shim serving `/_next/image` locally, which still wouldn't reflect the real production app, or removing `next/image` from these components at the source, which is out of scope for an additive sync).
